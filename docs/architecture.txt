REUSE AND RELOAD FOUNDATION — design and scope

Client -> SQLite key lookup -> alias/output authorization -> validate targets
       -> bounded admission
       -> breaker admission -> Redis reservation -> provider attempt
       -> JSON decode / owned SSE reader -> deadline-bounded downstream writes
       -> idempotent reconciliation -> at most one eligible fallback attempt

The gateway reuses one HTTP client/transport. Each provider operation uses
its request context. Redirects are disabled. Upstream errors are reduced to
fixed messages, and logs contain only request IDs, configured aliases,
provider names, durations, outcomes, and cache state. Authentication queries SQLite by credential hash; provider credentials are held
in memory because upstream calls require them.

STREAM OWNERSHIP DECISION

The HTTP handler owns the upstream response body. It calls Next(ctx)
synchronously and always closes the stream/body. No producer goroutine
or application event queue exists. A slow downstream naturally pauses
upstream reads; TCP buffers remain bounded and every write has a deadline.
Scanner/event and total-byte limits prevent accumulating arbitrarily large
SSE events or streams. First-event parsing occurs before header commitment.
After commitment, failure gets a sanitized SSE error and no success marker.
A successful terminal marker also requires a known finish reason. Usage
is normalized separately, including Anthropic cumulative usage updates.

HTTP/1.1 is deliberate for this milestone: a connection-level idle read
deadline belongs to one request. The shared transport limits idle and active
connections per host. HTTP/2 multiplexing would require a different idle
stream timeout mechanism; a connection deadline must not expire unrelated
streams. The overall context handles total request lifetime.

SIGTERM marks unready and stops admission before draining. All requests
inherit a root context. If the shared shutdown deadline expires, the root
is canceled and connections are closed. Exhausting the drain budget exits
with failure, making incomplete shutdown visible. Deadline error writes
have a small separate bounded window; they do not restart upstream work.

ACCOUNTING AND ROUTING DECISION

Each upstream attempt owns a distinct reservation. Both bucket and reservation
keys share a Redis hash tag. Atomic Lua scripts use Redis TIME and integer
milli-tokens. TTLs cover outstanding reconciliation and all debt refill.
Unknown usage keeps the whole debit, including failed upstream HTTP calls.
Only successful complete provider results with all reliable counters qualify
for reconciliation to actual usage; partial counters never become zero.
Expired records do not mint credit. Settled markers precede refund writes so
an unexpected Redis write failure can lose a refund but cannot refund twice.
Redis clients disable command retries; reservation replays with the same ID
and amount are idempotent while pending. An ambiguous admission error fails
closed with no upstream execution. Policy mismatch also fails closed.

Provider attempts are capped at two, one per configured target. Each uses a
remaining overall deadline bounded by its own timeout. Input is validated
against all targets before any reservation. Transient failures, 429, and 5xx
can trigger fallback only before commitment. Jittered delay and Retry-After
must fit the remaining deadline. The first attempt is reconciled before the
second reservation. A failed reconciliation blocks fallback. An interrupted
stream never switches providers; it retains unknown usage even if a partial
usage event was seen. Once the provider terminal marker is received, final
usage can be reconciled even if a downstream terminal write fails.

Circuit breakers are local, keyed by protocol, base URL, credential digest,
and upstream model. A mutex protects closed/open/half-open state. Failure
windows and open intervals use an injected clock in tests. Generation-tagged
completion tickets prevent old requests from closing a newly open breaker.
At most one half-open probe executes. Client cancellation, validation, and
local Redis failure do not poison provider health.

Readiness checks Redis and SQLite key reads; inference fails closed without shared admission.
Existing streams do not depend on Redis to deliver their remaining output.
Reconciliation is a bounded best-effort operation even on caller cancellation;
errors retain conservative debits and emit an explicit loss signal. SQLite key lookup occurs on every request, so a committed revocation takes
effect on the next request. Attempts and client outcomes are also queued for
SQLite persistence, with explicit loss counters.

COALESCING AND CACHE DECISION

Both a route flag and the SQLite key permission must allow reuse. Streaming
bypasses it. A bounded Redis cache stores only complete normalized successful
responses and usage provenance. Key ID, alias, effective output bound, original
canonical inputs, adapter version and route/credential fingerprint define the
identity. Canonicalization preserves message/text order, whitespace, numeric
spelling, and omitted versus explicit values. Entry size and TTL are bounded.
Cache failures become misses when mandatory limiter operations remain healthy.

Each caller reserves admission before lookup. Hits/followers refund their
unused reservation. A shared owner uses the first reservation only for the
matching primary attempt, releasing it if the breaker skips that target.
Each fallback attempt still has its own debit and reconciliation. A group
owns a deadline bounded by the initiator's original deadline, independent of
caller cancellation. It may continue and populate cache after all callers
leave. Active jobs own upstream slots; waiters and output writers are bounded.
The group does not coordinate provider execution across processes.

Shared usage is a distinct synthetic execution bundle. Client rows link to
it and own zero attempts. The worker atomically persists each execution and
its attempts. Client summaries filter out execution rows; upstream summaries
join attempts to their single owner. Cached/client completion tokens cannot
inflate provider consumption. SQLite schema v2 migrates existing rows to the
client kind while preserving key identities, revocation state and usage.

RELOAD DECISION

A validated deep copy is atomically published through atomic.Pointer. Each
request loads it once before authentication and retains it through retries,
streaming or shared execution. Credentials and process settings remain fixed.
Changed route behavior requires a higher declared revision. Fingerprints also
include resolved credential identities to protect restart/rotation boundaries.
Invalid candidates never replace the last good snapshot. Breaker pointers
are reused for unchanged upstream identities; old maps live only as long as
requests pin them. SIGHUP loads the file synchronously and logs acceptance or
rejection. New aliases still require explicit SQLite key authorization.

SQLITE OWNERSHIP AND LOSS DECISION

SQLite stores hashes and policies, never plaintext keys or request bodies.
The environment bootstrap key is imported once by hash; revoked imports are
not reactivated. New key secrets are CSPRNG-generated and returned only in
the creation response. Model aliases and maximum output are enforced from
the queried key metadata. Stable key IDs and pinned capacity/refill policies
are now used for Redis reservations; policy changes require a new key ID.

One writer connection serializes admin writes and usage transactions. Four
read connections use WAL with bounded busy/operation timeouts. Authentication
queries do not share the usage queue. SQLite key-read failure fails inference
closed; an already admitted stream continues. Usage-only write failure keeps
serving and exposes accounting loss through logs and /admin/status.

A request owns at most two attempt records. After completion it submits one
metadata-only snapshot to a bounded worker queue, with no producer goroutine
or retry queue. One transaction writes an owning client/execution bundle and its attempts.
Provider usage belongs to attempts; returned completion usage belongs to the
client result. Partial/interrupted counters are unknown, never inferred zero.
Failed persistence drops the whole bundle and increments explicit counters.
Queue overflow also counts lost requests and attempts without blocking on I/O.

SIGTERM drains HTTP first, then the usage worker under the same shutdown
context. Expiry cancels outstanding writes, reports undrained work, and returns
failure. A canceled worker accounts for queued losses before cleanup; process
exit can prevent final counters from being observed. There is no promise of
crash-safe delivery for an in-memory queue. Process counters reset; committed
SQLite rows persist. Admin aggregates are bounded and parameterized, separate
for clients and attempts so fallback does not double-count client completion.

Observability boundary
======================
Each Server owns a private Prometheus registry; tests and multiple gateways
never share global collectors. Client HTTP observations include authentication
failures and downstream delivery. The reusable execution engine records each
actual upstream attempt exactly once, including work whose callers canceled.
Client latency and first text use a monotonic clock. Stored attempt duration
has millisecond resolution. Provider tokens require trustworthy final usage;
unknown usage is counted separately, never guessed from cache deliveries.

Label allowlists are immutable startup aliases/providers, with a fixed other
bucket. Outcomes, cache states, token kinds and request modes are internal
finite enums. No upstream model or routing generation is a label. Runtime
gauges read atomics, channel sizes, worker stats and the current immutable
routing snapshot. Breakers are read under their own locks without transitions.
No scrape performs Redis or SQLite network/SQL operations.

Both TCP listeners bind before serving; management bind errors fail startup.
Metrics and explicitly enabled pprof use a dedicated ServeMux. Inference never
mounts that mux. Loopback-only profiling and explicit remote management opt-in
are validated before resources open. In-flight management handlers and profile
durations are bounded, and shutdown drains both listeners concurrently under
the same overall deadline used for shared jobs and usage persistence.

The optional Compose monitoring profile uses pinned Prometheus/Grafana images,
read-only provisioning, host loopback ports, two-hour/256MB Prometheus retention,
and named volumes. Dashboard panels use the stable gateway-prometheus datasource
UID. scripts/monitoring_acceptance.py checks target health, actual first-text
observations, dashboard/datasource provisioning and all panel expressions via
HTTP APIs. No browser automation or paid provider traffic is required.
