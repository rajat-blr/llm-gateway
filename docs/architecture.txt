RESILIENCE FOUNDATION — design and scope

Client -> authentication -> validate every target -> bounded admission
       -> breaker admission -> Redis reservation -> provider attempt
       -> JSON decode / owned SSE reader -> deadline-bounded downstream writes
       -> idempotent reconciliation -> at most one eligible fallback attempt

The gateway reuses one HTTP client/transport. Each provider operation uses
its request context. Redirects are disabled. Upstream errors are reduced to
fixed messages, and logs contain only request IDs, configured aliases,
provider names, durations, outcomes, and cache state. Authentication compares a SHA-256 bootstrap key hash; provider credentials are held
in memory because upstream calls require them.

STREAM OWNERSHIP DECISION

The HTTP handler owns the upstream response body. It calls Next(ctx)
synchronously and always closes the stream/body. No producer goroutine
or application event queue exists. A slow downstream naturally pauses
upstream reads; TCP buffers remain bounded and every write has a deadline.
Scanner/event and total-byte limits prevent accumulating arbitrarily large
SSE events or streams. First-event parsing occurs before header commitment.
After commitment, failure gets a sanitized SSE error and no success marker.
A successful terminal marker also requires a known finish reason. Usage
is normalized separately, including Anthropic cumulative usage updates.

HTTP/1.1 is deliberate for this milestone: a connection-level idle read
deadline belongs to one request. The shared transport limits idle and active
connections per host. HTTP/2 multiplexing would require a different idle
stream timeout mechanism; a connection deadline must not expire unrelated
streams. The overall context handles total request lifetime.

SIGTERM marks unready and stops admission before draining. All requests
inherit a root context. If the shared shutdown deadline expires, the root
is canceled and connections are closed. Exhausting the drain budget exits
with failure, making incomplete shutdown visible. Deadline error writes
have a small separate bounded window; they do not restart upstream work.

ACCOUNTING AND ROUTING DECISION

Each upstream attempt owns a distinct reservation. Both bucket and reservation
keys share a Redis hash tag. Atomic Lua scripts use Redis TIME and integer
milli-tokens. TTLs cover outstanding reconciliation and all debt refill.
Unknown usage keeps the whole debit, including failed upstream HTTP calls.
Only successful complete provider results with all reliable counters qualify
for reconciliation to actual usage; partial counters never become zero.
Expired records do not mint credit. Settled markers precede refund writes so
an unexpected Redis write failure can lose a refund but cannot refund twice.
Redis clients disable command retries; reservation replays with the same ID
and amount are idempotent while pending. An ambiguous admission error fails
closed with no upstream execution. Policy mismatch also fails closed.

Provider attempts are capped at two, one per configured target. Each uses a
remaining overall deadline bounded by its own timeout. Input is validated
against all targets before any reservation. Transient failures, 429, and 5xx
can trigger fallback only before commitment. Jittered delay and Retry-After
must fit the remaining deadline. The first attempt is reconciled before the
second reservation. A failed reconciliation blocks fallback. An interrupted
stream never switches providers; it retains unknown usage even if a partial
usage event was seen. Once the provider terminal marker is received, final
usage can be reconciled even if a downstream terminal write fails.

Circuit breakers are local, keyed by protocol, base URL, credential digest,
and upstream model. A mutex protects closed/open/half-open state. Failure
windows and open intervals use an injected clock in tests. Generation-tagged
completion tickets prevent old requests from closing a newly open breaker.
At most one half-open probe executes. Client cancellation, validation, and
local Redis failure do not poison provider health.

Readiness checks Redis; inference fails closed without shared admission.
Existing streams do not depend on Redis to deliver their remaining output.
Reconciliation is a bounded best-effort operation even on caller cancellation;
errors retain conservative debits and emit an explicit loss signal. Bootstrap
authentication still needs SQLite key lookup for immediate revocation. Attempt
records are JSON logs until SQLite persistence is implemented.

COALESCING DECISION — pending implementation

Reuse must be enabled by both key and route, and only for non-streaming
calls. Keys must include key identity, alias, route revision, adapter schema,
and every effective generation input. Shared execution must own a bounded
context independent of callers; each caller can stop waiting independently.
Process-local singleflight does not prevent duplicate cross-instance work.

RELEASE GATES STILL OPEN

SQLite keys/attempt persistence and failure/overflow visibility; exact caching and follower cancellation; immutable SIGHUP
snapshots; metrics and dashboard; repeated resource soak runs; comparable
load tests, profiles, and a measured optimization. The protocol tests and
SDK demo establish a foundation, not completion of the full PRD.
